# ResumeSetu

**AI-assisted resume ↔ job-description matching, ATS calibration, tailored rewrites and an application tracker — sold as a one-person MicroSaaS (admin-configured Pro price; ₹249/mo default).**

ResumeSetu scans a candidate's resume against a real job description, returns an *auditable* 0–100 match score with keyword gaps, and (for Pro members) generates a grounded, single-column Word rewrite plus a role-specific cover letter. An owner-only admin console handles users, LLM routing, payments, security logs and platform settings.

> **This repository had no README.** This file plus `docs/` and `screenshots/` were generated by a full code + running-system audit (frontend, backend, DB schema, live API) and are also bundled as `ResumeSetu-complete-docs.zip`.

## What it does

1. **Scan** — paste a job description, upload a PDF/DOCX (≤ 5 MB) or pick a bundled sample. `POST /api/check` runs a deterministic ATS engine and answers in ~200 ms with a blended score.
2. **Understand the gap** — matched keywords vs. missing gaps, skill delta, alignment summary, measured *document checks*, and STAR bullet rewrite guidance. Raw analysis JSON is inspectable in-app.
3. **Tailor (Pro)** — a background queue rewrites the resume for the specific role; every generated claim is re-validated against the source resume (`lib/grounding.ts`) and unsupported metrics are redacted.
4. **Apply** — single-column `.docx` export, role-specific cover letter, and a 5-stage application CRM (Saved → Applied → Interview → Offer → Rejected) with auto-created rows per scan.
5. **Operate (owner)** — admin console for users/roles/Pro grants/bans, LLM registry + per-task primary/fallback routing, manual payment verification, security audit log, health matrix and platform settings (free limit, Pro price, maintenance mode, prompt-injection shield).

### Honesty design (the product's differentiator)

The codebase deliberately refuses to invent numbers:

- The **score is never produced by an LLM** — it comes from a deterministic TF-IDF / cosine engine (`lib/ats-engine.ts`, 55 % keyword coverage + 45 % semantic proximity). The `score` LLM task has *no* `match_score` field on purpose (`lib/schemas.ts`).
- Unscorable input (empty JD, no keyword signal) returns **422 with an explanation** instead of a fake score.
- "ATS parser test", "OCR quality", "impact verb ratio" render as **"Not tested" / "Not measured"** rather than made-up percentages.
- Missing keywords are only reported as *gaps you did not evidence* — the engine never adds keywords to inflate coverage.
- Landing-page employer logos and named case studies were removed as unverifiable (see comments in `src/views/LandingPage.tsx`).

## Tech stack

| Layer | Choice |
| --- | --- |
| Frontend | React 19 + Vite 8 + TypeScript, Tailwind CSS v4 (`@theme` tokens), `motion`, `lenis`, `lucide-react` / `hugeicons` |
| Auth | Clerk (hash routing, embedded `<SignIn>`/`<SignUp>` dialog) → server session exchange |
| Backend | Express 4 on `tsx` (`server.ts`), also wrapped in `serverless-http` for Netlify Functions |
| Sessions | HMAC-signed httpOnly cookie (`lib/session.ts`), 30-day TTL, constant-time compare |
| Database | Supabase Postgres (service-role server adapter `lib/supabase-db.ts`); legacy JSON file kept only as migration source |
| Files | PDF (`pdf-parse`) / DOCX (`mammoth`) parsing, AES-256-GCM encryption server-side, private Supabase Storage bucket |
| AI | Gemini / Groq / OpenAI / Anthropic adapters behind a task router (`score`, `tailor`, `cover_letter`, `resume_parse`) with primary + fallback bindings |
| Payments | Manual Telegram-activated upgrade with HMAC-signed reference + admin-verified ledger |
| Deploy | Netlify (`npm run build && npm run check:deploy` → `dist`, `/api/*` → `/.netlify/functions/api/*`) |

## Quick start

```bash
# 1. Install (Node >= 20)
npm install

# 2. Configure
cp .env.example .env      # then fill in values

# 3. Run the dev server (Express + Vite middleware on :3000)
npm run dev
```

**Minimum `.env` to boot locally:** `SESSION_SECRET` (≥ 16 chars), `STORAGE_ENCRYPTION_KEY` (32 chars), `VITE_CLERK_PUBLISHABLE_KEY` + `CLERK_SECRET_KEY`, `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`, and at least one AI provider key (`GEMINI_API_KEY` / `GROQ_API_KEY` / …). Without a Clerk publishable key the app deliberately renders a loud "missing key" notice instead of a dead sign-in box.
